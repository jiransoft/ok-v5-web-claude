# 피할 것

이 문체에서 어긋나는 패턴과 고치는 방향이다. `--rewrite` 에서 가장 자주 손대는 순서로 적었다.

## 도입

- **정의·배경으로 시작.** "Spring의 @TransactionalEventListener는 트랜잭션 동기화 콜백을 등록하는 어노테이션입니다." → 사건으로 바꾼다. "어느 날 검색 색인에 빠진 문서가 하나 발견됐습니다."
- **"이 글에서는 ~를 다룹니다" 예고문.** 첫 문단에 두지 않는다. 필요하면 도입 장면 뒤 두 번째 문단에서 한 문장으로.
- **질문으로 시작.** "여러분은 배치 완료를 어떻게 판정하시나요?" → 저희가 겪은 장면으로.

## 제목

- **명사구 제목.** "배치 스케줄러 개선기", "트랜잭션 이벤트 처리 전략" → 서술형 문장. "@Scheduled 한 줄로 버티다, 트리거를 밖으로 꺼낸 이야기".
- **라벨형 섹션 제목.** "문제 정의", "해결 방안", "결론" → 그 섹션의 결론 한 줄. "락으로 하나만 돌리면, 그 하나가 사라질 때 멈춥니다".
- **번호·이모지 제목.** "1️⃣ 배경" 같은 표기를 쓰지 않는다.

## 어조

- **구어체 혼입.** "~에요", "~거든요", "~죠", "~잖아요", "~더라고요" → 합쇼체로.
- **1인칭 흔들림.** 한 글에서 "저희"와 "우리", "flex는"이 섞임 → "저희"로 통일.
- **독자 훈계.** "반드시 ~해야 합니다", "~하지 마세요" → 저희의 선택과 그 이유로. 일반화하려면 조건을 붙인다.
- **마케팅 어휘와 감탄.** "혁신적인", "획기적으로", "놀라운", "완벽하게" → 삭제하거나 구체적 관찰로 바꾼다.
- **근거 없는 단정.** "이 방식이 정답입니다" → "저희 상황에서는 이 선택이 맞았고, 그 조건은 ~입니다".

## 구조

- **대안 기각 없음.** 문제에서 곧장 해법으로 감 → 독자가 먼저 떠올릴 해법을 인용문으로 꺼내 한 문단씩 기각한다.
- **대가·한계 섹션 없음.** 해법의 장점만 나열 → 포기한 것, 남은 숙제, 적용 안 되는 조건을 별도 섹션으로.
- **요약형 마무리.** "결론적으로 ~를 통해 ~를 달성했습니다", "마지막으로 정리하면" → 도입 장면으로 돌아와 한 문장 명제 또는 되묻기.
- **감사 인사·CTA로 끝냄.** "읽어주셔서 감사합니다" → 마지막 문장은 명제여야 한다. (원문의 채용 CTA 는 블로그 플랫폼이 붙이는 것이라 본문에 넣지 않는다.)

## 문장

- **em-dash(—) 부연.** "plan은 그 질문에 답하지 못합니다 — 비교하는 것은 두 개의 의도이기 때문입니다" → 마침표로 끊는다. "plan은 그 질문에 답하지 못합니다. plan이 비교하는 것은 두 개의 의도입니다."
- **불릿 나열.** 첫째/둘째/셋째를 불릿으로 → 각 항목을 "첫째, ~" 로 시작하는 문단으로.
- **표·코드 과다.** 표 셋, 코드 다섯 → 표 하나, 코드 둘 이내. 표는 뒤에 산문으로 다시 읽어준다.
- **한 문장에 주장 둘.** "A이며 또한 B이므로 C입니다" → 문장을 나눈다. 명제 하나에 문장 하나.
- **같은 종결 세 번 연속.** "~인 셈입니다. ~인 셈입니다. ~인 셈입니다." → 하나를 "~라는 뜻입니다" 또는 단문으로.
- **볼드 남발.** 한 섹션에 볼드 세 곳 → 명제 한 문장만.

## 사실

- **만들어 넣은 수치·연구.** "연구에 따르면 40% 향상" 처럼 출처 없는 숫자 → 사용자가 준 출처가 없으면 `[확인 필요: 수치 출처]` 로 남긴다.
- **꼬리표 없는 수치.** "기동 시간이 70초 줄었습니다" → "실측입니다" 또는 "가정값을 넣은 자체 추산입니다" 를 붙인다.
- **발췌 복사.** exemplars.md 의 문장을 그대로 옮김 → 구조만 빌리고 문장은 새로 쓴다.
