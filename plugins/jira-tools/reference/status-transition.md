# 이슈 상태 전환 규약

`jira-tools` 의 상태를 바꾸는 스킬(`impl-issue` · `resolve-issue` · `complete-issue`)이 공유한다.
각 스킬은 **목표 키**만 정하고, 전환 고르기·실행·재확인은 이 문서대로 한다.

## 왜 이름이 아니라 카테고리인가

전환 이름은 워크플로우마다 다르고(`해결됨` · `해결함` · `완료` · `Done`) 나중에 바뀔 수도 있다.
이름 일치로만 찾으면 이름이 바뀐 날부터 **경고 한 줄만 남기고 조용히 전환을 건너뛴다.**

Jira 의 모든 상태는 고정된 세 카테고리 중 하나에 속한다.

| `statusCategory.key` | 뜻 | 이름 예시 |
|----------------------|-----|----------|
| `new` | 시작 전 | 열림 · 다시 열림 · To Do |
| `indeterminate` | 진행 중 | 진행 중 · 확인중 · In Progress |
| `done` | 완료 | 해결됨 · 해결함 · 완료 · Done |

## 목표 키

| 목표 키 | 카테고리 | 관용 이름 (이름에 포함) | 쓰는 곳 |
|---------|----------|------------------------|---------|
| `inProgress` | `indeterminate` | 진행 · In Progress | `impl-issue` 시작, `complete-issue` 검증 실패 |
| `review` | `indeterminate` | 확인 · 검토 · 검증 · Review · QA | `impl-issue` 댓글 등록 후, `resolve-issue` 댓글 등록 후 |
| `done` | `done` | 해결 · 완료 · Done · Resolved | `complete-issue` 검증 통과 |

`inProgress` 와 `review` 는 **카테고리가 같다.** 카테고리만으로는 둘을 가를 수 없으므로 3단계 사다리에
둘을 구분하는 규칙이 따로 있다. 이름이 두 관용 이름에 모두 걸리면(`Review in progress` · `QA 진행 중`)
**`review` 로 본다** — 건너뛰기 판단과 사다리 모두 이 기준을 쓴다.

설정 키 `jira-tools.transitions` 에 목표 키별 이름을 고정할 수 있다 (선택):

```json
"transitions": { "inProgress": "진행 중", "review": "확인중", "done": "해결함" }
```

값은 **전환 이름이나 도착 상태 이름** 중 어느 쪽이어도 된다 (`setup` 은 상태 이름을 적는다).

## 1. 현재 상태와 전환 목록 조회

```bash
curl -s -u "$email:$token" "$baseUrl/rest/api/3/issue/{이슈키}?fields=status" \
  | jq -r '.fields.status | "\(.name)\t\(.statusCategory.key)"'
curl -s -u "$email:$token" "$baseUrl/rest/api/3/issue/{이슈키}/transitions" \
  | jq -r '.transitions[] | "\(.id)\t\(.name)\t\(.to.name)\t\(.to.statusCategory.key)"'
```

두 번째 응답의 각 줄은 `전환 id · 전환 이름 · 도착 상태 이름 · 도착 카테고리` 다.

## 2. 이미 목표 상태면 건너뛴다

아래 중 하나면 전환하지 않고 결과에 `이미 {현재 상태}` 로 적는다.

- `jira-tools.transitions.<목표 키>` 값이 현재 상태 이름과 같다 (다른 목표 키의 값은 보지 않는다)
- `done`: 현재 카테고리가 `done` 이다
- `review`: 현재 카테고리가 `indeterminate` 이고 현재 상태 이름에 `review` 의 관용 이름이 들어 있다
- `inProgress`: 현재 카테고리가 `indeterminate` 이고 현재 상태 이름에 `inProgress` 의 관용 이름은 들어 있되
  `review` 의 관용 이름은 들어 있지 않다

`확인중` 인 이슈에 `impl-issue` 를 다시 돌리면 `inProgress` 의 관용 이름에 걸리지 않으므로 건너뛰지 않고
`진행 중` 으로 되돌린다. 의도한 동작이다.

## 3. 전환 선택 사다리

위에서부터 내려가며 하나로 좁혀지면 멈춘다. 이름 비교는 전환 이름과 도착 상태 이름 **둘 다** 본다.

1. **설정 이름** — `jira-tools.transitions.<목표 키>` 가 있고, 그 이름의 전환 중 도착 상태가 현재 상태와
   다른 것이 조회 결과에 있으면 그것을 쓴다
2. **카테고리로 좁힌다** — 도착 카테고리가 목표와 같고, 도착 상태가 현재 상태와 다른 전환만 남긴다
3. **같은 카테고리의 다른 목표를 걸러낸다**
   - `review`: 관용 이름이 들어간 후보만 남긴다. 안 들어간 후보는 전부 뺀다. 분석·구현을 끝낸 이슈를
     `진행 중` 같은 엉뚱한 상태로 옮기지 않기 위해서다
   - `inProgress`: `review` 의 관용 이름이 들어간 후보를 뺀다. 구현을 시작하는 이슈를 `확인중` 으로 옮기지 않기 위해서다
4. **후보가 1개면** 그것을 쓴다
5. **후보가 2개 이상이면** 목표 키의 관용 이름으로 한 번 더 좁힌다. 1개가 되면 그것을 쓴다
6. **그래도 2개 이상이면 사용자에게 묻는다** — AskUserQuestion 으로 후보(`전환 이름 → 도착 상태`)와
   `전환하지 않음` 을 보여준다. 임의로 하나를 고르지 않는다
7. **후보가 0개면 전환하지 않는다** — 현재 상태에서 목표로 가는 길이 없다는 뜻이다. 경고를 내고 결과에 사유를 적는다

## 4. 실행과 재확인

고른 전환의 `id` 로 실행한다.

```bash
curl -s -u "$email:$token" -X POST "$baseUrl/rest/api/3/issue/{이슈키}/transitions" \
  -H "Content-Type: application/json" -d '{"transition": {"id": "{전환 id}"}}'
```

실행한 뒤에는 **1단계의 상태 조회를 다시 돌려 실제로 바뀌었는지 확인한다.** 화면의 필수 필드가 비어 있으면
전환 API 가 204 를 돌려주고도 상태를 바꾸지 않는 경우가 있다. 읽어온 상태가 고른 전환의 도착 상태와
다르면 전환 실패로 보고하고, 성공으로 적지 않는다.

## 5. 실패해도 스킬은 계속한다

전환을 못 했다고 해서(2단계 건너뜀, 7단계 후보 없음, 4단계 재확인 실패) 스킬의 다른 단계를 멈추지 않는다.
결과 출력의 `상태` 줄에 사유를 적고 다음 단계로 간다.

6단계에서 사용자가 골랐거나 7단계로 빠졌다면, 스킬의 "plugins.json 설정 권고" 블록에
`transitions.<목표 키>` 를 넣어 다음 실행부터 묻지 않도록 안내한다.
