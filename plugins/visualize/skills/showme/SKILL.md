# Showme Skill

기술 개념을 **깊이 있게, 정직하게, 코드로 검증하며** 설명하고 **직접 보여주는** 스킬.
"개념 → 공식 문서 근거 → 우리 코드 실측 매칭 → 다이어그램/비교표 → 실행·시각화" 흐름을 따른다.

## 입력 파싱

- `$ARGUMENTS` 에서 설명 대상 개념을 추출한다.
- 플래그:
  - **기본값은 SHOW 모드** — 별도 플래그가 없으면 실행 데모 + 인터랙티브 HTML 생성/브라우저 오픈까지 수행한다.
  - `--text` (또는 `text`, `--no-show`, `--quiet`) 가 있으면 **TEXT 모드** (텍스트 다이어그램 + 비교표만. 브라우저/실행 없음).

## 핵심 원칙 (반드시 준수)

1. **공식 문서 우선**: 개념 정의는 기억이 아니라 공식 명세/레퍼런스를 근거로 한다. 불확실하면 WebSearch/WebFetch로 확인하고, 확인 못 한 부분은 "추정"으로 명시한다.
2. **코드 주장은 실측**: "우리 앱에서는 ~다"라고 말하기 전에 반드시 Grep/Glob/Read로 실제 레포 코드를 확인한다. 가정으로 단언 금지. (의존성 라이브러리 내부가 필요하면 아래 4단계의 생태계별 검증법을 쓴다. 바이너리 아티팩트는 `grep`이 신뢰 불가 → 전용 도구 사용)
3. **정직한 정정**: 검증 결과가 앞선 설명과 모순되면, 얼버무리지 말고 명시적으로 "정정합니다"라고 바로잡는다.
4. **계층적 설명**: 한 줄 요약 → 큰 그림(다이어그램) → 세부. 앞서 설명한 개념과 연결고리를 만든다.
5. **끝에 다음 단계 훅**: 더 깊이 볼 만한 다음 주제를 1~2개 제안한다.

## 절차

### 1단계 — 개념의 표준 정의 (공식 문서 기반)
- 대상 개념이 무엇인지 공식 명세/레퍼런스 기준으로 정의한다.
- 헷갈리기 쉬운 동음이의(예: 자료구조 `hash table` vs 클래스 `java.util.Hashtable`)가 있으면 먼저 구분한다.
- 불확실한 사실은 WebSearch로 확인. 확인 불가 시 "추정" 표기.

### 2단계 — 큰 그림 ASCII 다이어그램
- 구조/관계/흐름을 텍스트 다이어그램으로 그린다 (포함관계, 호출 흐름, 계층 등).
- 가능하면 "왜 이렇게 설계됐나"의 의도를 함께.

### 3단계 — 우리 코드 실측 매칭
- **생략 분기(우리 코드와 무관한 개념)**: 개념이 현재 레포의 언어/생태계/도메인과 무관하거나(예: Python 레포에서 JVM 내부 질문), 가벼운 탐색(`Grep`/`Glob`)으로 사용처가 전혀 없다고 확인되면 **이 단계를 생략**한다. 이때 "이 개념은 현재 레포에서 사용되지 않습니다(또는 무관합니다)"라고 한 줄로 명시하고 바로 4단계로 넘어간다. 억지 매칭 금지.
- 먼저 이 레포의 **언어/생태계를 식별**한다 (빌드 파일·락파일로 판단: `build.gradle`/`pom.xml`→JVM, `package.json`→Node, `pyproject.toml`/`requirements.txt`→Python, `go.mod`→Go, `Cargo.toml`→Rust 등).
- 이 개념이 현재 레포에서 어떻게 쓰이는지 **실제로 찾는다**:
  - `Grep`/`Glob`으로 관련 클래스/설정/어노테이션/심볼 위치 파악
  - `Read`로 실제 코드 확인
- 찾은 사실만 진술. 코드에 줄번호(`file:line`)를 붙인다.
- 표준 개념 ↔ 우리 코드를 **좌우 매칭 비교표**(마크다운 테이블)로 정리한다.

### 4단계 — 비교/대조표
- A vs B (예: HashMap vs Hashtable), 또는 표준 vs 우리구현, 또는 과거 vs 현재 등 대조가 이해를 돕는 지점은 표로 만든다.

### 5단계 — 실행·시각화 (기본 수행 / `--text` 면 생략)
TEXT 모드(`--text`)가 아니면 **항상** 다음 중 개념에 맞는 것을 골라 만든다:
- **실행 데모**: 동작을 증명하는 최소 코드를 `/tmp/`에 작성하고 `Bash`로 실제 실행해 출력을 보여준다.
  - 레포 생태계에 맞는 러너를 쓴다: Java `java /tmp/Demo.java` (single-file), Python `python3 /tmp/demo.py`, Node `node /tmp/demo.mjs`, Go `go run /tmp/demo.go` 등. 러너가 없으면 코드를 보여주되 "미실행"임을 명시한다.
  - 단순 설명을 넘어 "주장 증명"에 쓴다 (예: 스트림 유출 시 예외 발생, 충돌/리해싱 실제 관측).
- **인터랙티브 HTML**: 자료구조/알고리즘/구조 매핑을 다룰 때 `/tmp/<주제>.html` 에 인터랙티브 시각화(다크테마, 버튼/입력으로 조작)를 작성하고 브라우저에 띄운다.
  - 공식↔우리코드 매핑은 좌우 2단 패널 HTML로.
- 만든 파일 경로를 사용자에게 알려준다 (`/tmp/...` 에 남음).
- claude.ai 웹 Artifacts와 달리 채팅 인라인 렌더는 불가하므로 "브라우저 탭으로 열린다"는 점을 한 번 안내.

#### 브라우저 열기 (OS 분기 + 폴백)
플랫폼에 맞는 명령을 쓴다. 실패하면 강제로 다시 띄우려 하지 말고 **파일 경로만 안내**한다.
```bash
# macOS: open / Linux: xdg-open / Windows(WSL): explorer.exe 또는 cmd.exe /c start
case "$(uname -s)" in
  Darwin) open "$F" ;;
  Linux)  command -v xdg-open >/dev/null && xdg-open "$F" || echo "수동으로 열기: $F" ;;
  *)      command -v cmd.exe >/dev/null && cmd.exe /c start "$F" || echo "수동으로 열기: $F" ;;
esac
```

### 6단계 — 요약 + 다음 단계 훅
- 한 문단 요약 (핵심 한 줄 + 표준/우리앱 구분).
- 더 깊이 볼 다음 주제 1~2개 제안 ("~를 이어서 볼까요?").

## 출력 스타일
- 한국어. 계층적 헤딩(`##`), 다이어그램은 코드블록, 대조는 마크다운 표.
- 장황한 나열 금지 — 핵심을 굵게, 비유는 짧게.
- 코드 인용 시 줄번호 표기. 추정과 검증된 사실을 구분해 표기.

## 안티패턴 (하지 말 것)
- 레포 코드를 안 보고 "아마 ~일 것" 으로 단언.
- 공식 근거 없이 동작 원리 확정.
- 기본(SHOW) 모드인데 그냥 코드만 보여주고 실행/오픈 안 함. → 기본은 반드시 실행·시각화까지 간다.
- `--text` 인데 브라우저를 열거나 코드를 실행.
- 실행/오픈이 환경 문제로 실패했는데 성공한 척하기. → 실패하면 "미실행/수동 열기 필요"로 정직하게 알리고 파일 경로를 준다.
- 검증이 앞말과 어긋나는데 슬쩍 넘어가기.

## 참고: 검증 도구 메모 (생태계별)
- **공통**: 단일 spec/클래스 동작 확인은 실제 실행이 가장 강력. 바이너리 아티팩트를 `grep`으로 문자열 매칭하면 인코딩/NUL 바이트 때문에 누락될 수 있음 → 전용 디컴파일/심볼 도구 우선.
- **JVM (Gradle/Maven)**: jar 내부 확인 — `find ~/.gradle/caches -name "<lib>*.jar"` (또는 `~/.m2/repository`) → `unzip -p`(소스) / `javap -p -c`(바이트코드). 멀티릴리스 jar는 `META-INF/versions/9/...` 확인. 단일 파일 실행 `java /tmp/Demo.java`.
- **Node (npm/pnpm/yarn)**: 의존성 실코드는 `node_modules/<pkg>/` 에 그대로 있음 → `Read`로 직접 확인. 타입은 `node_modules/<pkg>/*.d.ts`. 동작 검증은 `node /tmp/demo.mjs`.
- **Python (pip/poetry/uv)**: 설치 패키지는 site-packages(`python3 -c "import <pkg>, os; print(os.path.dirname(<pkg>.__file__))"`)에서 소스 확인. 동작 검증은 `python3 /tmp/demo.py`. C확장은 소스 부재 가능 → 공식 문서로.
- **Go**: 모듈 소스는 `$(go env GOMODCACHE)/<module>@<ver>/` 에 있음. 동작 검증은 `go run /tmp/demo.go`.
- **Rust**: 크레이트 소스는 `~/.cargo/registry/src/.../<crate>-<ver>/`. 문서는 `cargo doc`.
