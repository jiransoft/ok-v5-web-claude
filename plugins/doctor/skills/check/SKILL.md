# Doctor Check Skill

설치된 플러그인의 환경을 진단한다. **플러그인별 요구사항은 각 플러그인의 `doctor.json` 이 소유하고**,
이 스킬은 그 매니페스트를 읽어 실행하는 범용 러너다. 여기에 플러그인 이름을 하드코딩하지 않는다.

## 절차

1. **진단 실행**

   ```bash
   python3 "${CLAUDE_PLUGIN_ROOT}/scripts/check.py"
   ```

   `$ARGUMENTS` 에 `--deep` 이 있으면 붙인다 (훅 selfTest 까지 실행). 경로가 있으면 `--project <경로>`.

2. **결과 해석** — `## 판정 규칙` 으로 심각도를 확인한다. 스크립트 출력을 그대로 붙여넣지 말고
   오류·경고만 추려 사람이 읽을 형태로 정리한다.
3. **조치 제안** — `## 조치 원칙`. 오류마다 무엇을 하면 되는지 한 줄로 붙인다.
4. **사용자 확인 후 수정** — 승인 없이 파일·설정을 바꾸지 않는다.

## 종료코드

| 코드 | 의미 |
|------|------|
| `0` | 오류·경고 없음 |
| `1` | 경고만 있음 |
| `2` | 오류 있음 |

스크립트가 매니페스트를 하나도 못 찾으면 `2` 로 끝난다 — 플러그인 미설치·미갱신 신호다.

## 판정 규칙

**깨진 것만 오류다.** 설치된 모든 플러그인의 설정을 모든 프로젝트가 갖출 이유는 없다.

| 심각도 | 예 |
|--------|-----|
| ❌ 오류 | 필수 설정 키 누락, 필수 토큰 파일 없음·빈 파일, 필수 CLI 없음, 필수 MCP 서버 미설정, 훅 스크립트 유실, `plugins.json` 파싱 실패 |
| ⚠️ 경고 | 토큰 파일 권한이 느슨함, 알 수 없는 설정 키·섹션(개명 후 구 키), 설치본 버전이 마켓플레이스보다 낡음, `plugins.json` 이 `.gitignore` 에 없음 |
| · 정보 | 이 프로젝트에서 안 쓰는 플러그인의 섹션 없음, 폴백이 있는 CLI 없음, 외부 마켓플레이스 플러그인 |

**개명 흔적은 경고로 잡힌다.** 매니페스트가 주장하지 않는 설정 섹션과, 활성 상태인데 매니페스트가
없는 플러그인이 각각 걸린다. 플러그인 이름이 바뀐 뒤 설정·설치가 따라오지 않은 상태다.

## 조치 원칙

- **자동 수정 금지.** 진단은 읽기 전용이다. 수정은 사용자에게 무엇을 왜 바꾸는지 말하고 승인받는다
- 설정 문제는 해당 플러그인의 셋업으로 보낸다 — 매니페스트의 `setup` 값이 그 명령이다
- 권한·설치 명령은 스크립트가 제안 문구에 담아 출력한다. 그대로 안내하고, 실행은 사용자 승인 후에 한다
- 토큰 파일 내용은 읽지 않는다. 존재·크기·권한만 본다
- 매니페스트를 이 스킬이 고치지 않는다. 요구사항이 틀렸으면 그 플러그인의 `doctor.json` 을 고쳐야 한다

## 매니페스트가 없는 플러그인

`doctor.json` 이 없으면 진단 대상이 아니다. 두 경우를 구분한다.

- **외부 마켓플레이스 플러그인** — 정보로만 표시한다. 지원 대상이 아니다
- **매니페스트를 동봉하는 마켓플레이스의 플러그인인데 없음** — 경고다. 개명·미갱신이 원인이다

## 출력 형식

플러그인별로 묶어 심각도 높은 것부터 보고한다. 정상 항목은 개수로 줄인다.

```
❌ jira-tools
   - `jira-tools` 필수 키 누락: email, apiTokenFile → /jira-tools:setup
   - 정상 5건 (토큰 파일, curl·jq·git·pandoc)

⚠️ 프로젝트 · 설치 위생
   - 매니페스트가 없는 설정 섹션: gitlab-workflow — 개명 후 남은 구 키
   - `.claude/plugins.json` 이 .gitignore 에 없음

정상: hud, git-workflow, figma-tools, code-review-suite, visualize, arch-tools
```

오류가 없으면 한 줄로 끝낸다 — 정상인 것을 길게 나열하지 않는다.

## 주의사항

- 매니페스트 스키마는 [reference/manifest-schema.md](../../reference/manifest-schema.md) 다
- `--deep` 은 훅 selfTest 를 실제로 실행한다. 느릴 수 있으니 기본으로 켜지 않는다
- 진단 결과의 "정상"은 **선언된 요구사항 기준**이다. 매니페스트가 낡았으면 통과해도 실제로는 깨질 수 있다
- MCP 서버 점검은 `~/.claude.json` 과 프로젝트 `.mcp.json` 의 선언 여부만 본다. 연결·인증 상태는 보지 않는다
